# v2.24.0 AI Company Pronunciation Release Design

## Context

The dictionary currently treats `simile` as the English literary term and
lists `sigh-MILE` as an alternate. In current AI-company usage, Simile's
co-founder and CEO Joon Sung Park says the company name as three syllables,
`SIM-uh-lee`; the supposed two-syllable `sigh-MILE` alternate is a
mispronunciation and
should not be presented as accepted.

A broader August 2026 scan found several new AI companies with unfamiliar
names. This release will only add candidates whose pronunciation can be
grounded in a creator/official statement or in a founder saying the name in
a timestamped recording. That keeps the release small and avoids converting
caption guesses or etymological inference into dictionary facts.

## Considered Approaches

### A. Correct only `simile`

This directly fixes the reported problem, but leaves three equally
well-evidenced AI-company names out of a release that is already refreshing
this section of the dictionary.

### B. Correct Simile and add every recent candidate

This would maximize entry count, but candidates such as NYAK still require
inference about spelling or sound. Entry count is not worth lowering the
dictionary's evidence standard.

### C. Correct Simile and add only creator-verified candidates (selected)

Update `simile` in place and add QualiKI, KugelAudio, and Gradium. All four
rows will use `creator-clarified` confidence and direct evidence. Defer NYAK
and other ordinary or weakly evidenced company names.

## Generated Artifacts and Product Facts

`data/pronunciations.tsv` remains the source of truth. The site data, word
pages, audio, Open Graph cards, sitemap/feed, Hugging Face export, VS Code
dictionary, and Chrome dictionary will be regenerated through the existing
repository tools.

The corpus grows from 1,880 to 1,883 entries. All three additions have citable
sources and are creator-clarified; the corrected Simile row moves from
community consensus to creator-clarified and gains a direct source. Therefore
the expected public totals become:

- 1,883 total entries;
- 1,263 entries with a citable source;
- 105 creator-clarified entries; and
- 174 contested entries (Simile is currently community consensus, not
  contested, so correcting it does not change this count).

The build output, rather than these arithmetic expectations, is authoritative.
All count-bearing current-product copy and the site footer will be updated to
the computed values and v2.24.0. Historical changelog sections remain
unchanged.

## Tests and Verification

Add a focused repository-fact test before editing the TSV. It must fail on
the current corpus and then assert:

- all four rows exist with the exact primary IPA, respelling, category,
  confidence, and source URL;
- `simile` has no alternate pronunciation or respelling; and
- every release source URL is non-empty and uses HTTPS.

Then run the repository's full release guards:

```text
node --test tools/test-v2-audio.mjs
python3 -m unittest tools/test_build_v2_data.py tools/test_make_og_all.py tools/test_chrome_dictionary.py
bash tools/lint-dict.sh
bash tools/smoke-test.sh
```

Also verify `./bin/say-it --json` for all four entries, play each entry through
the CLI, check that a second site build is clean, and audit the generated
entry/audio/OG files for all three new slugs.

## Release Procedure

Create a v2.24.0 changelog section describing the corrected Simile entry,
three additions, evidence standard, and regenerated integrations. Commit the
tested source and generated outputs to `main`, push them, and wait for the
required GitHub Actions and deployment checks on the final SHA. Only then
create and push annotated tag `v2.24.0` and publish the matching GitHub
Release. If automation creates a follow-up commit, rerun the release guards
against that final commit before tagging.

## Deferred

NYAK and any other candidate without sufficiently direct pronunciation
evidence remain unshipped. They can be added later when a founder or official
source makes the sound and canonical spelling unambiguous.
