# v2.23.1 Consistency Release Design

## Context

v2.23.0 shipped 1,880 dictionary entries. The follow-up commits on `main`
fixed hreflang clusters, missing OG cards, citations, and release-stat drift,
but those fixes are not represented by a newer tag or GitHub Release.

The audit also found three remaining consistency gaps:

1. The v2 homepage uses browser speech synthesis instead of the already
   fingerprinted `/audio/<slug>.mp3` corpus, so it does not play the same
   three-repeat, all-alternates audio promised by the CLI and word pages.
2. Public copy still says Windows/Linux are on the roadmap, describes the
   CLI as roughly 250 lines, and describes the TSV respelling column as an
   Apple phoneme payload.
3. Site builds do not trigger for several v2 source/generator files, while
   the per-word OG generator rewrites all 1,880 cards on every run.

## Considered Approaches

### A. Tag the current `main` only

Fastest, and it would put the post-v2.23.0 fixes into a release, but it would
leave the user-visible audio mismatch and the build churn in place.

### B. Small consistency patch, then tag (selected)

Fix canonical homepage playback, correct the stale product facts, complete
the build trigger set, and make OG generation incremental. This addresses
known defects without changing the dictionary or redesigning the site.

### C. Fold in homepage payload and browse rendering work

Reducing `data.js` and virtualizing/paginating 1,880 browse cards would
improve mobile performance, but it changes search/rendering behavior and
deserves a separate release with browser performance measurements.

## Design

### Canonical homepage audio

`SpeechCtx` will own one active `HTMLAudioElement`. Entry playback will:

1. stop prior HTML audio and Web Speech output;
2. derive the canonical per-character slug from the entry word;
3. play `/audio/<slug>.mp3`;
4. fall back once to Web Speech if the asset errors or `play()` rejects; and
5. ignore stale callbacks from a playback superseded by a newer click.

The Web Speech fallback will retain all alternate respellings in generated
v2 data and mirror the canonical audible body: primary three times, then each
alternate prefixed by “or”. Direct free-text speech remains available for
UI features that are not dictionary-entry playback.

Hero, dictionary cards, and Famous entries will all use entry playback. UI
playing state will finish from the audio/fallback completion callback instead
of a fixed timer.

### Product facts

Source files, not generated artifacts, will be corrected:

- replace line-count marketing with the stable claim “one Bash CLI”;
- describe macOS, Linux, and Windows as shipped backends;
- describe `respelling_us` as an English-like respelling passed to OS TTS;
- state that the website uses the committed canonical MP3 and only falls back
  to Web Speech on playback failure; and
- bring repository guidance/design status in line with the shipped artifacts.

Generated `docs/v2/data.js`, `bundle.js`, and pages will be rebuilt from those
sources.

### Build reliability

The site workflow path filter will include v2 JSX sources and every generator
that feeds committed site output. Existing dictionary lint and smoke tests
remain unchanged.

### Incremental OG cards

`make-og-all.py` will store `docs/og/manifest.json`, mapping slug to a short
fingerprint of:

- an explicit renderer version;
- canvas and style constants; and
- every entry field visible on the card.

An existing non-empty PNG with the expected fingerprint is skipped. Missing
or stale cards are rendered and their fingerprint is updated. Removed
dictionary entries are removed from the manifest but image deletion remains
manual.

For the one-time migration, an explicit bootstrap command will trust only
existing non-empty assets after the current lint has proved complete. Normal
CI will never bootstrap implicitly. A second run must make no file changes.

## Error Handling

- MP3 failure falls back once; cancellation never starts a stale fallback.
- A missing Web Speech API leaves the click silent but does not throw.
- A corrupt OG manifest is treated as empty and causes safe regeneration.
- Bootstrap fails if any expected card is missing or empty.
- OG rendering failures leave the prior manifest stamp unchanged.

## Verification

- Unit tests cover audio success, failure fallback, cancellation races,
  three repeats, and multiple alternates.
- Unit tests cover OG first render, current skip, changed-field render,
  missing-file render, corrupt manifest recovery, and bootstrap refusal.
- Rebuild v2 data/bundle/site and assert a second build is clean.
- Run dictionary lint, CLI smoke tests, OG manifest check, and relevant
  extension builds.
- Browser-smoke the homepage with successful MP3 playback and forced 404
  fallback.
- Push `main`, wait for required Actions/Vercel success, tag `v2.23.1`, and
  publish a GitHub Release describing only this patch scope.

## Deferred

Homepage payload reduction, browse-card pagination/virtualization, new
dictionary entries, Search Console manual inspection, and broader MCP
contract tests are separate follow-ups.
