# v2.23.1 Consistency Release Design

## Context

v2.23.0 shipped 1,880 dictionary entries. The follow-up commits on `main`
fixed hreflang clusters, missing OG cards, citations, and release-stat drift,
but those fixes are not represented by a newer tag or GitHub Release.

The audit also found three remaining consistency gaps:

1. The v2 homepage uses browser speech synthesis instead of the already
   fingerprinted `/audio/<slug>.mp3` corpus, so it does not play the same
   three-repeat, all-alternates audio promised by the CLI and word pages.
2. Public copy still says Windows/Linux are on the roadmap, describes the
   CLI as roughly 250 lines, and describes the TSV respelling column as an
   Apple phoneme payload.
3. Site builds do not trigger for several v2 source/generator files, while
   the per-word OG generator rewrites all 1,880 cards on every run.

## Considered Approaches

### A. Tag the current `main` only

Fastest, and it would put the post-v2.23.0 fixes into a release, but it would
leave the user-visible audio mismatch and the build churn in place.

### B. Small consistency patch, then tag (selected)

Fix canonical homepage playback, correct the stale product facts, complete
the build trigger set, and make OG generation incremental. This addresses
known defects without changing the dictionary or redesigning the site.

### C. Fold in homepage payload and browse rendering work

Reducing `data.js` and virtualizing/paginating 1,880 browse cards would
improve mobile performance, but it changes search/rendering behavior and
deserves a separate release with browser performance measurements.

## Design

### Canonical homepage audio

`build-v2-data.py` will emit the canonical slug plus both the compatibility
`alt` field and an `alts: string[]` field. Generating the slug in Python keeps
client playback identical to the Python audio/SEO generators for punctuation
and Unicode names.

`SpeechCtx` will own one active playback request. Its public contract is:

```text
playEntry(entry, { onDone }) -> requestId
cancel(requestId)
speak(text, { onDone }) -> requestId
```

Every request calls `onDone({ requestId, status })` exactly once with
`ended`, `failed`, or `cancelled`. Components retain the returned ID and only
clear their own state for that ID. Entry playback will:

1. stop prior HTML audio and Web Speech output;
2. synchronously allocate a generation/request token;
3. play `/audio/<generated-slug>.mp3`;
4. fall back once to Web Speech if the asset errors or `play()` rejects; and
5. settle, but never start fallback, for stale callbacks from superseded
   playback.

The `error` event and rejected `play()` promise share one guarded fallback.
The Web Speech fallback mirrors the canonical audible body: primary three
times, then every trimmed non-empty alternate prefixed by “or”. Missing Web
Speech, utterance errors, and cancellation also settle the request exactly
once. Direct `speak()` first cancels active MP3/speech to prevent overlapping
output.

Hero, dictionary cards, Famous entries, Command Palette results, and
type-to-speak will all resolve the full generated dictionary entry and use
`playEntry`. Karaoke, quiz-answer text, and logo feedback remain intentional
free-text `speak()` uses. UI playing state will finish from the request
completion callback instead of a fixed timer. Hero auto-rotation pauses while
its audio is active so its label cannot change mid-playback.

### Product facts

Source files, not generated artifacts, will be corrected:

- replace line-count marketing with the stable claim “one Bash CLI”;
- describe macOS, Linux, and Windows as shipped backends;
- describe `respelling_us` as an English-like respelling passed to OS TTS;
- state that the website uses the committed canonical MP3 and only falls back
  to Web Speech on playback failure; and
- bring repository guidance/design status in line with the shipped artifacts.

Generated `docs/v2/data.js`, `bundle.js`, and pages will be rebuilt from those
sources.

### Build reliability

The site workflow path filter will include:

- `docs/v2/{audio,sections-1,sections-2,eggs,app}.jsx`;
- `tools/build-v2-data.py` and `tools/build-v2-bundle.sh`;
- `tools/build-entry-dates.py`, `build-scoreboard.py`, and `build-seo.py`;
- `tools/make-audio-all.py`, `make-og.py`, and `make-og-all.py`; and
- the new audio/OG test files.

Generated `bundle.js` and `data.js` are not trigger inputs. The existing CI
workflow will gain a release-guard job that runs the dependency-free Node
audio tests and Python OG tests; its push path filter will include the same
source and test files.

### Incremental OG cards

`make-og-all.py` will store an atomic, versioned
`docs/og/manifest.json` with `schema`, `renderer`, and `cards` keys. Each slug
maps to a short fingerprint of:

- an explicit renderer version;
- canvas and style constants; and
- every entry field visible on the card.

An existing non-empty PNG with the expected fingerprint is skipped. Missing
or stale cards are rendered via a temporary file and atomically replaced.
Removed dictionary entries are removed from the manifest but image deletion
remains manual. Duplicate generated slugs fail before any render starts.

The CLI modes are:

```text
python3 tools/make-og-all.py --bootstrap-existing
python3 tools/make-og-all.py --check
python3 tools/make-og-all.py
```

Bootstrap validates every expected non-empty PNG before atomically writing
stamps; it never renders. `--check` is read-only and fails on schema,
renderer, stamp, missing-file, or duplicate-slug drift. Normal CI never
bootstraps implicitly.

Migration order is fixed: run dictionary lint, bootstrap locally against the
post-v2.23.0 audited corpus, commit the manifest in the same implementation
commit, run `--check`, then push. This prevents the first CI run from
re-rendering the full corpus. A second normal run must make no file changes.
Any render failure leaves the prior manifest untouched so the next run
retries; partially rendered PNGs are safe because their manifest stamps do
not advance.

## Error Handling

- MP3 failure falls back once; cancellation settles the old request and never
  starts a stale fallback.
- Missing Web Speech or a speech error settles as `failed` without throwing.
- A corrupt OG manifest is treated as empty and causes safe regeneration.
- Bootstrap fails if any expected card is missing or empty.
- OG rendering failures leave the prior manifest stamp unchanged.

## Verification

- `node --test tools/test-v2-audio.mjs` evaluates the plain `SpeechCtx` prefix
  with `node:vm` and mocked Audio/Web Speech globals. It covers MP3 success,
  error/rejection de-duplication, a superseded rejection that must not
  fallback, exactly-once cancellation, missing/speech-error failure, direct
  speech cancelling MP3, three repeats, and multiple alternates.
- `python3 -m unittest tools/test_make_og_all.py` covers first render, current
  skip, entry/style/renderer invalidation, missing-file render, corrupt
  manifest recovery, atomic failure behavior, duplicate slugs, bootstrap
  refusal, and read-only `--check`.
- Rebuild v2 data/bundle/site and assert a second build is clean.
- Run dictionary lint, CLI smoke tests, OG manifest check, and relevant
  extension builds.
- Browser-smoke Hero, card, Famous, Command Palette, and type-to-speak with
  successful MP3 playback, plus one forced 404 fallback.
- Verify all stale-copy source locations explicitly: Hero/Terminal metrics,
  WordGrid aside, Command Palette footer, site footer version, generated
  FAQs, README, CLAUDE.md, DESIGN.md, and the noindex v2 scaffold metadata.
  Historical CHANGELOG text and the intentional old promo asset URL stay
  unchanged.
- Push `main`, pull the CI-generated site commit, and identify the final
  `origin/main` SHA. Wait for Actions and Vercel success on that SHA; only then
  create `v2.23.1` at that exact SHA and publish a GitHub Release describing
  this patch scope.

## Deferred

Homepage payload reduction, browse-card pagination/virtualization, new
dictionary entries, Search Console manual inspection, and broader MCP
contract tests are separate follow-ups.
